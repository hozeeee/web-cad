## 简介
本指南帮助新用户快速搭建 web-cad 项目的本地开发环境，完成依赖安装、启动开发服务器、构建产物以及预览。项目基于 Vite + React，提供标准单页应用与单文件打包两种构建模式，并内置类型检查、测试与端到端测试脚本。

## 环境要求
- Node.js：^22.22.2 或 >=24.15.0（由包管理器在引擎校验中强制）
- npm：随 Node.js 安装即可使用
- 操作系统：Windows / macOS / Linux 均可

说明：
- 项目通过 engines 字段声明了 Node.js 版本范围，确保开发与构建行为一致。
- TypeScript 目标为 ES2022，模块解析采用 Bundler 模式，适合现代浏览器与工具链。

## 启动开发服务器
- 启动默认开发服务器：npm run dev
- 该命令会启动 Vite 开发服务器，并监听所有网卡（host 0.0.0.0），便于局域网访问。

常见用法：
- 本机访问：打开浏览器访问 http://localhost:5173
- 局域网访问：使用本机 IP 地址访问（例如 http://192.168.x.x:5173）

注意：
- 如果端口被占用，Vite 会自动尝试下一个可用端口。
- 如需指定端口，可在命令后追加参数，例如：npm run dev -- --port 3000

## 构建与预览
- 构建标准产物：npm run build:standard
  - 输出目录：dist/standard
- 构建单文件产物：npm run build:single
  - 输出目录：dist/single
- 一键完整构建（含类型检查与双模式构建）：npm run build
- 预览标准产物：npm run preview
- 预览单文件产物：npm run preview:single

说明：
- 标准构建用于常规部署；单文件构建将所有资源内联到一个 HTML 文件中，便于离线分发。
- 预览命令会启动静态服务器，默认 host 0.0.0.0，便于局域网访问。

## 配置说明
- Vite 基础路径：base 设置为相对路径 ./，适用于非根路径部署场景。
- 插件：启用 @vitejs/plugin-react 以支持 React JSX。
- 构建输出：
  - 标准模式：dist/standard
  - 单文件模式：dist/single（启用 vite-plugin-singlefile）
- TypeScript：
  - target: ES2022
  - module: ESNext
  - strict: true
  - noEmit: true（仅类型检查，不产出 TS 文件）
- Playwright E2E：
  - 自动启动开发服务器与静态资源服务
  - 开发服务器端口固定为 5186，严格端口模式
  - 静态资源服务监听 127.0.0.1:4174，映射 dist/standard 与 dist/single

## 最佳实践
- 使用与项目一致的 Node.js 版本，避免工具链差异导致的构建问题。
- 在团队中统一使用 npm 进行依赖管理，保持 lock 文件一致。
- 提交前运行类型检查与 Lint：
  - npm run typecheck
  - npm run lint:fix
- 本地调试时优先使用 npm run dev，开启热更新提升效率。
- 发布前执行完整构建：
  - npm run build
- 需要离线分发或简单托管时，使用单文件构建产物 dist/single/index.html。

## 故障排除
- 无法启动开发服务器（端口冲突）
  - 现象：报错提示端口已被占用
  - 解决：更换端口，例如 npm run dev -- --port 3000
  - 依据：Playwright 配置中使用 --strictPort 固定端口，便于 E2E 稳定运行
- 无法在局域网访问
  - 现象：本机可访问，其他设备无法访问
  - 解决：确认已启用 host 0.0.0.0（默认已启用），并确保防火墙允许对应端口
- 构建失败或类型检查报错
  - 现象：npm run build 报类型错误
  - 解决：先运行 npm run typecheck 定位并修复类型问题，再重新构建
- 预览页面空白或资源加载失败
  - 现象：预览时出现 404 或空白页
  - 解决：确认已执行 npm run build 生成 dist 目录；使用 npm run preview 或 npm run preview:single 分别预览标准与单文件产物
- E2E 测试无法连接开发服务器
  - 现象：Playwright 启动失败或超时
  - 解决：确保未手动占用 5186 端口；必要时清理残留进程后重试
  - 依据：E2E 配置自动启动开发服务器与静态资源服务，端口分别为 5186 与 4174
